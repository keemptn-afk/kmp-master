Post-Order Tracking · Detail Spec

Tracking System.

Position lifecycle 5 phases · MFE/MAE/path/virtual SL-TP · 93-column CSV schema · เก็บไว้เป็น blueprint หาก EA หายก็ใช้เอกสารนี้สร้างใหม่ได้

01

Position Lifecycle Overview

ทุก order มี 5 phases ของการติดตาม · 1 trade = 1 CSV row × 93 columns (รวม execution metadata)

Phase 1
1× per trade
Order open · capture pattern + 40 indicators
Phase 2
Every tick
MFE/MAE update · best/worst price
Phase 3
9× per trade
Path snapshots · 1/6/12/24/48/72/120/168/240h
Phase 4
Every tick
Virtual SL/TP hits · 4+4 levels
Phase 5
1× per trade
Position close · CSV row written
02

Phase 1 — Order Open (1× per trade)

PHASE 1 Order Opens — Snapshot Frozen trigger: pattern fires

เมื่อ pattern X ตรวจจับได้ที่บาร์ K ปิด → เปิด market order ที่ first tick ของบาร์ K+1 → จองช่อง slot ใน g_tracked[] array

ข้อมูลที่ถูก capture (frozen) ตลอดอายุ trade:

// Pattern identification
g_tracked[slot].pattern_id          = pid;            // e.g., 5
g_tracked[slot].pattern_name        = "Engulf_Trap_Bull";
g_tracked[slot].pattern_category    = "A";
g_tracked[slot].pattern_direction   = +1;             // from metadata
g_tracked[slot].trade_direction     = +1;             // actual trade dir

// Entry context (NEW v3.1: separated intended vs actual fill)
g_tracked[slot].entry_price          = actual_broker_fill;  // updated in OnTradeTransaction DEAL_ENTRY_IN
g_tracked[slot].intended_entry_price = current_ASK;         // frozen: what we requested
g_tracked[slot].spread_at_entry_pts  = SymbolInfoInteger(SYMBOL_SPREAD);  // for execution analysis
g_tracked[slot].entry_atr            = snap.atr_14;
g_tracked[slot].open_time            = now;
g_tracked[slot].expire_time          = now + 240h (calendar OR trading per WeekendMode);
g_tracked[slot].lot                  = computed_from_risk_pct;
g_tracked[slot].entry_balance        = AccountBalance();

// 40-field indicator snapshot — ALL frozen
g_tracked[slot].indicators          = snap;           // EMA9/20/50/100/200,
                                                       // BB upper/middle/lower/width/%B,
                                                       // ATR14/50, RSI7/14, Stoch K/D,
                                                       // MACD/signal, Volume ratio,
                                                       // ADX/DI+/DI-, Session, Hour, DoW

// 177-pattern context (which OTHER patterns also fired this bar)
g_tracked[slot].all_patterns        = flags;

// Bar K anatomy (signal bar)
g_tracked[slot].bar_open/high/low/close = ...;
g_tracked[slot].bar_body            = MathAbs(close - open);
g_tracked[slot].bar_upper_wick      = high - MathMax(open, close);
g_tracked[slot].bar_lower_wick      = MathMin(open, close) - low;
g_tracked[slot].bar_range           = high - low;

// Entry quality (timing relative to bar K)
g_tracked[slot].entry_vs_body_pct       = ...;        // %ของ body
g_tracked[slot].entry_vs_range_pct      = ...;        // %ของ range
g_tracked[slot].entry_distance_from_high_atr = ...;
g_tracked[slot].entry_distance_from_low_atr  = ...;
g_tracked[slot].entry_quality       = "AT_LOW";       // computed label

// Reset tracking arrays for this slot
ResetPathSnapshots(slot);    // 9 paths set to {captured=false}
ResetSLTPHits(slot);          // 4 SL + 4 TP flags = false
max_favorable = max_adverse = entry_price;
03

Phase 2 — MFE/MAE (every tick)

PHASE 2 Maximum Favorable / Adverse Excursion trigger: every tick

รัน UpdateActivePositions() ทุก tick · update best/worst price ที่เคยเห็น + เวลาที่เกิด

double current = (direction == +1) ? BID : ASK;   // fill side

// MFE — best price ever (Long: highest, Short: lowest)
if (direction == +1 && current > max_favorable) {
   max_favorable = current;
   mfe_time = now;
   hours_to_mfe = (now - open_time) / 3600;
}

// MAE — worst price ever
if (direction == +1 && current < max_adverse) {
   max_adverse = current;
   mae_time = now;
   hours_to_mae = (now - open_time) / 3600;
}

// Convert to ATR units (for cross-pattern/cross-symbol comparison)
max_favorable_atr = (max_favorable - entry_price) / entry_atr;
max_adverse_atr  = (entry_price - max_adverse)  / entry_atr;
ใช้หาอะไร: mfe_atr distribution ต่อ pattern → กำหนด TP ceiling realistic · mae_atr distribution → กำหนด SL minimum สำหรับ pattern นั้น
04

Phase 3 — Path Snapshots (9 milestones)

PHASE 3 Time-Series Snapshots (1/6/12/24/48/72/120/168/240h) trigger: hours_held threshold first crossed

ที่จุดเวลาแต่ละ milestone (calendar hours) → capture price + pnl_atr · ทำได้ครั้งเดียวต่อ milestone (sticky)

// Run every tick, but capture once per threshold
double hours_held = (now - open_time) / 3600;
double dir_pnl_atr = (direction == +1)
                    ? (current - entry_price) / entry_atr
                    : (entry_price - current) / entry_atr;

// Each path bucket captured ONCE when threshold first reached
if (!path_1h.captured && hours_held >= 1) {
   path_1h.captured    = true;
   path_1h.price       = current;
   path_1h.pnl_atr     = dir_pnl_atr;
   path_1h.hour_offset = 1;
}
// ... repeat for 6, 12, 24, 48, 72, 120, 168, 240 hours

ใช้หาอะไร: Time-decay curve — ดูว่า edge ของ pattern X ขึ้นที่ชั่วโมงไหน หายที่ชั่วโมงไหน · ใช้ optimize hold time per pattern
หมายเหตุ TF-dependent: M15 trades มักไม่ถึง 240h (closes ก่อนด้วย TP/SL) → path columns ปลายๆ จะว่าง · นี่ไม่ใช่ bug — เป็น behavior ที่ถูกต้อง
05

Phase 4 — Virtual SL/TP Tracking (every tick)

PHASE 4 Virtual Stop Loss / Take Profit Hits trigger: every tick

"Virtual" = ไม่ปิด position จริง · แค่ track ว่าราคาเคยถึง level นั้นหรือไม่ · ใช้ simulate "ถ้าตั้ง SL=X, TP=Y จะเกิดอะไร"

// Sticky SL hit flags (once true, stays true)
if (max_adverse_atr >= 0.5) sl_05_hit = true;
if (max_adverse_atr >= 1.0) sl_10_hit = true;
if (max_adverse_atr >= 2.0) sl_20_hit = true;
if (max_adverse_atr >= 3.0) sl_30_hit = true;

// TP hits with timestamp (FIRST crossing only)
if (max_favorable_atr >= 1.0 && !tp_10_hit) {
   tp_10_hit  = true;
   tp_10_time = now;            // hours_to_tp10 derived later
}
// ... repeat for 2.0x, 3.0x, 5.0x ATR

06

Phase 5 — Position Close (1× per trade)

PHASE 5 Final Exit + CSV Write trigger: time-stop, OnTradeTransaction, or backtest end

3 วิธีที่ position จะปิด:

  • Time-stop: now >= expire_time → EA สั่ง PositionClose() + exit_reason = "TIME_STOP"
  • Broker close: margin call, manual close, etc. → OnTradeTransaction fires + exit_reason = "EXPERT" or other
  • Backtest end: OnDeinit force-close active positions + exit_reason = "BACKTEST_END"
// OnTradeTransaction handler

// (NEW v3.1) DEAL_ENTRY_IN — capture actual broker fill price for slippage
if(deal_entry_type == DEAL_ENTRY_IN) {
   g_tracked[slot].entry_price = deal_price;  // actual fill, replaces intended
   return;  // (intended_entry_price stays frozen for slippage analysis)
}

// DEAL_ENTRY_OUT — close handler
g_tracked[slot].close_time          = deal_time;
g_tracked[slot].exit_price          = deal_price;
g_tracked[slot].spread_at_exit_pts  = SymbolInfoInteger(SYMBOL_SPREAD);  // NEW v3.1
g_tracked[slot].pnl_dollars         = profit + swap + commission;
g_tracked[slot].pnl_atr             = (deal_price - entry_price) / entry_atr * direction;
g_tracked[slot].hours_held          = (deal_time - open_time) / 3600;
g_tracked[slot].direction_correct   = (pnl_dollars > 0);

// Write 93-column CSV row (90 + 3 execution metadata)
g_Logger.WriteRecord(g_tracked[slot]);

// Free slot
g_tracked[slot].active = false;
g_tracked[slot].ticket = 0;
Exit Reasons in CSV: TIME_STOP (default 240h) · EXPERT (broker confirmed) · SL_HIT · TP_HIT · BACKTEST_END (force close at OnDeinit)

Recovery Use Cases

Optimal SL per pattern SELECT pattern_id, percentile(mae_atr, 90) FROM trades GROUP BY pattern_id
→ minimum SL = 90th percentile of MAE
Optimal TP per pattern SELECT pattern_id, AVG(tp_20_hit), AVG(hours_to_tp20) FROM trades GROUP BY pattern_id
→ TP=2 ATR works if hit_rate > 60%
Best filter regime SELECT trend_regime, COUNT(*), AVG(pnl_atr) FROM trades WHERE pattern_id=5 GROUP BY trend_regime
→ ใช้ pattern X เฉพาะ regime ที่ EV positive
Time-decay analysis For each pattern: average path_1h, 6h, 24h, 72h, 240h
→ plot curve · ดูว่า edge เสริมหรือสลายเมื่อเวลาผ่าน
Confluence stacking SELECT pattern_id, AVG(direction_correct), patterns_long_score FROM trades GROUP BY pattern_id, patterns_long_score
→ ถ้ามี ≥3 long patterns พร้อมกัน, win rate เพิ่มไหม?
Cross-asset edge transfer Pattern X works on EUR H4 — does it work on XAU H1?
→ ATR-normalized comparison via mfe_atr/mae_atr
