Order Execution Specs

Order Type Decision Tree
Market order: สำหรับ patterns ที่ trigger ต้อง execute ทันที (Engulfing, BOS, FVG entries on close)
Limit order: สำหรับ pullback patterns (Order Block, Breaker Block, FVG fill, POC bounce)
Stop order: สำหรับ breakout patterns (BOS confirmation, Failed Breakout reversal)
Pending expiry: 1 bar เท่านั้น · ถ้าไม่ trigger = cancel
Slippage & Requote Handling
Max slippage: XAU 5 points · BTC 50 points · EUR 0.5 pips
Requote response: retry 2 ครั้ง · ถ้าเกิน skip trade
Partial fill: accept ถ้า fill ≥ 50% ของ lot ที่ขอ · ที่เหลือ cancel
Latency check: ถ้า ping > 200ms → skip trade
All-In Cost Per Trade Modeling
Cost = Spread + Commission + Swap (ถ้าถือข้ามคืน)
XAU spread (Exness Pro): ~0.15 USD avg · commission ~$3.5/lot round-turn
BTC spread: ~$15 avg · commission ~$0.08% · swap ค่อนข้างใหญ่
EUR spread: ~0.5 pip avg · commission ~$3.5/lot · swap แล้วแต่ direction
EA ต้อง: reject trade ถ้า expected_pnl < 3 × all-in cost

Position Sizing · Exact Formula

Lot Size Calculation
risk_amount = account_balance × risk_per_trade_pct (เช่น 0.5% = 0.005)
sl_distance = entry_price - sl_price (in price units)
sl_in_pips = sl_distance / pip_size_for_symbol
pip_value = (lot_size × contract_size × pip_size) / quote_currency_rate

lot = risk_amount / (sl_in_pips × pip_value_per_lot)
lot = max(min_lot, min(max_lot, round(lot, 2))) Pip values reference (Exness Pro · standard lot 1.0):
BTCUSD: 1 pip = 0.01 = $1 / lot · contract size = 1 BTC
XAUUSD: 1 pip = 0.01 = $1 / lot · contract size = 100 oz
EURUSD: 1 pip = 0.0001 = $10 / lot · contract size = 100,000 EUR
Constraints
Min lot: 0.01 (Exness)
Max lot per trade: 5% ของ account ÷ symbol margin requirement
Margin check: free_margin / required_margin ≥ 3.0 ก่อน open
Total exposure cap: รวม margin used ทุก position ≤ 30% account
Adaptive Sizing (Live Tuning)
Half Kelly: base_risk × 0.5 × (WR_rolling_30 - (1-WR_rolling_30)/RR)
Equity curve scaling:
DD < 5% from peak → 100% size
DD 5-10% → 75% size
DD 10-15% → 50% size
DD > 15% → kill switch (manual review)
WR-based: ถ้า rolling WR ของ pattern < 45% ใน 30 trades → reduce 50%

Exit Logic · Beyond Static SL/TP

Trailing Stop Logic
Activation: เมื่อ MFE ≥ 1.5×ATR (price moved 1.5 ATR in profit direction)
Distance: trail by 1.0×ATR ตาม recent swing high/low
Min profit lock: ค้าง break-even + 0.3×ATR (ห้ามขาดทุนหลัง trail trigger)
Step: update trail ทุก bar close ใหม่ ไม่ใช่ tick
Break-Even Shift
เมื่อ MFE ≥ 1.0×ATR → ย้าย SL ไป entry + spread + 0.1×ATR
ป้องกัน winning trade กลายเป็น loser
apply กับทุก pattern ยกเว้น scalp patterns (TP เร็ว < 12h)
Partial Close Strategy
50% TP1: ที่ 2×ATR · close 50% ของ position · move SL ไป break-even
30% TP2: ที่ 3×ATR · close 30% เพิ่ม · trail remainder
20% Runner: ที่ 5-10×ATR หรือ time-stop
เพิ่ม win rate effective + ลด equity volatility
Conditional Early Exit
Reverse signal: ถ้าเกิด opposite-direction Tier-A pattern ใน HTF → exit immediately
Volatility spike: ถ้า vol_regime เปลี่ยนเป็น HIGH สำหรับ XAU H4 (ผิด profile) → close 50%
Time-stop: 72 hours สำหรับ H4/H1 · 24 hours สำหรับ M15
End-of-week: ปิดทุก position ที่ MFE > 0 ก่อน Friday close

Conflict Resolution
เมื่อ Universal Stack signal long แต่ Per-Asset Module signal short ใน symbol/TF เดียวกัน:
Rule 1: ใช้ Universal Stack (Tier-A) เป็น primary · ปฏิเสธ module signal
Rule 2: ยกเว้นถ้า module pattern WR ≥ 65% ใน dataset นั้น → ใช้ module
Rule 3: ถ้า conflict ใน HTF (H4 long แต่ H1 short) → skip ทั้งหมด · wait alignment
Position Correlation Limits
Max same-direction positions: 3 (เช่น BTC + XAU + EUR ทั้ง long ได้)
Max same-asset positions: 1 (ห้าม XAU H4 + XAU H1 พร้อมกัน)
Correlation pairs: BTC ↔ ETH (ถ้าเพิ่ม) = correlated · นับ 1 slot
XAU ↔ Silver = correlated · EUR ↔ GBP = correlated
Pattern Weight Blending (Confluence)
เมื่อหลาย patterns trigger ใน bar เดียวกัน:
Weighted score: sum(tier_weight × wr_weight) per direction
Tier-A weight = 1.0 · Tier-B = 0.7 · Tier-C = 0.4
WR weight = (WR - 50) / 50 (ปรับตาม WR ของ pattern × ds นั้น)
Trade trigger: ถ้า score ≥ 1.5 · open position ตาม direction ที่ score สูงกว่า
Direction conflict: ถ้า score long และ short ใกล้กัน (diff < 0.3) → skip

Failsafe · Recovery · Kill Switch

Kill Switch Triggers (auto-stop EA)
Trigger ใดก็ได้ → EA หยุด trade ทันที + email/notify Keem:
Equity DD > 15% from peak
5 consecutive losses ใน symbol เดียว
Daily loss > 3% ของ account
Live WR < 40% ใน rolling 50 trades
Spread spike > 5x ของ avg → skip trades ใน symbol นั้น
Connection loss > 60 sec → close all market orders ที่ MFE > 0
Cooldown & Recovery
After single big loss (loss > 2× avg loss): pause 30 min · ห้าม revenge trade
After kill switch: ต้อง manual review checklist + restart command · ห้าม auto-resume
After daily loss limit: pause until 00:00 UTC วันถัดไป
After weekly loss limit: pause until Monday open
Connection & Order Failures
Order rejected: log + retry 1 ครั้ง · ถ้า rejected อีก = skip
Server time drift > 5 sec: alert · skip trades ใหม่
Account margin call: emergency close all (priority: largest unrealized loss first)
Manual emergency: hotkey on chart = close all + disable EA
Restart procedure: ทบทวน open positions vs MT5 records · sync state file
Anti-Curve-Fitting Safeguards
Walk-forward validation: ทุก 3 เดือน re-run backtest บน OOS data
Disable threshold: pattern ที่ live WR ต่างจาก backtest WR > 15% นาน 60 trades = disable
Sample size minimum: ห้ามใช้ pattern ที่ไม่เคยมี n ≥ 30 ใน backtest
Robustness test: ทุก pattern ต้อง profitable ใน 3+ datasets ก่อน deploy live

Backtesting · Optimization · Walk-Forward

Validation Framework Before Live
1. In-Sample (IS) Backtest: 60% ของ data (Jan-Mar 2026) · ใช้ optimize parameters
2. Out-of-Sample (OOS) Test: 40% ของ data (Apr-May 2026) · ห้ามแตะ parameters
3. Pass criteria: OOS Profit Factor ≥ 70% ของ IS · OOS WR ≥ IS WR - 5%
4. Walk-Forward: rolling 3-month optimize · 1-month forward test · 12 cycles
5. Robustness: ผ่าน OOS ทุก cycle ห้ามแย่กว่า 80% ของ IS
Parameter Sensitivity (Anti-Overfitting)
ทุก parameter ต้อง test ±20% range รอบค่าที่ optimize
ถ้า P&L drops > 30% เมื่อ shift parameter 10% → overfit · ห้ามใช้
Robust parameter: P&L stable ใน plateau ±20% range
Optimization variables (จำกัด): SL multiplier, TP multiplier, ADX threshold, trailing distance · ห้าม optimize เกิน 5 ตัวพร้อมกัน
Monte Carlo & Robustness
Monte Carlo: shuffle trade order 1,000 times · ดู max DD distribution
Worst-case DD ห้ามเกิน 2× ของ historical max DD
Slippage stress test: เพิ่ม slippage 50%-100% · ดูผล P&L · ต้อง profitable
Spread doubling test: ใช้ spread × 2 ใน backtest · ต้องยังคุ้มต้นทุน
Pattern drop test: ลบ pattern ที่ดีที่สุด 1 ตัว · ดูว่า EA ยัง profitable
Optimization Schedule
Initial: ใช้ 4 เดือน data ปัจจุบัน · IS 2.5 mo + OOS 1.5 mo
Quarterly re-optimize: ทุก 3 เดือน live ทำ walk-forward
Annual full review: re-evaluate tier rankings · อัปเดต blacklist
Trigger re-optimize sooner: ถ้า live P&L < 60% ของ expected เป็นเวลา 30 days

MT5 Implementation · Code Architecture

Bar Detection · Tick Handling
Trigger: OnTick() · check IsNewBar() กับ Time[0]
Reason: trigger ที่ bar close เท่านั้น · backtest กับ live ตรงกัน
Implementation: static datetime lastBar = 0;
datetime curBar = iTime(_Symbol, _Period, 0);
if (curBar != lastBar) {
  lastBar = curBar;
  CheckPatterns();
  ManagePositions();
}
Magic Number Scheme
Format: 7-digit · AABBCDD
AA = Account (10-99) · BB = Strategy version (01-99) · C = Asset (1=BTC, 2=XAU, 3=EUR)
DD = Pattern ID (01-80)
Example: 1042077 = Account 10, v04, XAU, P77 Mitigation_Block_Bull
เหตุผล: filter trades โดย symbol + pattern ในการวิเคราะห์
Multi-Symbol · Single EA Architecture
1 EA วิ่งบน 1 chart (เช่น XAUUSD H1) แต่ trade ได้ทุก symbol/TF
Loop: for each symbol in [BTCUSD, XAUUSD, EURUSD] × each TF [H4, H1, M15]

Performance Metrics · Equity Analysis

Beyond P&L · Required Metrics
Profit Factor = sum(wins) / sum(losses) · target ≥ 1.5 · live
Expectancy = (WR × avg_win) - ((1-WR) × avg_loss) · target > 0 หลังหัก cost
Sharpe Ratio = (annualized return) / (annualized stddev) · target ≥ 1.0
Sortino Ratio = (return) / (downside stddev) · target ≥ 1.5 · ดูเฉพาะ DD volatility
Calmar Ratio = annual return / max DD · target ≥ 1.0
Recovery Factor = net_profit / max_drawdown · target ≥ 3.0
R-Multiple Distribution Tracking
R-multiple = trade_pnl / initial_risk_amount
เก็บ histogram per pattern · ดู distribution
Healthy: mean ≥ 0.3R · positive skew · max R ≥ 5R
Red flags: negative skew · long left tail · max R < 2R = no big winners
Visualize ทุกเดือน ใน performance dashboard
Equity Curve Analysis
Track: balance + equity curve · save daily
Underwater curve: %DD จาก peak ทุกวัน
Recovery time: วันที่ใช้กลับ peak หลัง DD
Streak analysis: max consecutive wins/losses · alert ถ้าผิดปกติ
Live vs backtest comparison: overlay graph · alert ถ้า divergence > 20%
Per-Pattern Quality Score (post-live)
quality = (live_PF × 0.3) + (live_WR/100 × 0.2) +
  (live_expectancy × 0.3) + (sample_size_score × 0.2)
sample_size_score = min(1.0, n_trades / 100) Pattern ที่ quality < 0.5 → demote tier · > 0.8 → promote

State Persistence · Reliability · Black Swan

State Persistence
Save state file ทุก: trade open · trade close · parameter change
Path: MQL5/Files/KMP_State_{account}.json
Content: open positions · pattern signals queued · daily P&L · DD tracker · cooldown timers
Recovery on restart: read state file · sync with MT5 positions · resume cooldowns
Position Reconciliation (After Crash/Restart)
1. Compare MT5 OrdersTotal() vs state file open positions
2. Missing in MT5 (closed during crash) → log + remove from state
3. Missing in state (manual trade?) → adopt or alert (parameter ADOPT_MANUAL_TRADES)
4. Verify SL/TP attached · re-attach if missing
5. Resume management ตาม pattern original rules
Black Swan Protection
Flash crash detection: ราคาเคลื่อน > 5×ATR ใน 1 minute → close all + pause 1h
Spread spike emergency: spread > 10× ของ avg → skip all entries · existing positions trail tighter
Weekend gap risk: Friday 21:00 GMT → ปิดทุก position ที่ MFE < 1×ATR (ไม่มี cushion)
Liquidity crisis: tick volume drops > 80% from avg + spread widens → emergency close + pause
Broker outage: connection loss > 5 min → close all market on reconnect (assume worst-case fills)
Hardware/VPS Considerations
VPS: deploy on VPS <5ms latency to broker server (Equinix LD4 for Exness London)
Backup VPS: secondary VPS in different region · auto-failover ถ้า primary down
Terminal stability: restart MT5 weekly (memory leak prevention)
Monitor uptime: external ping check · alert ถ้า VPS down > 5 min
Notifications: Telegram bot สำหรับ alerts (kill switch, big win/loss, errors)
